## What problem did this solve?

Customers relied on a legacy reporting tool that took several seconds to load each chart and often timed out on large accounts. Support tickets about slow reports were the #1 category.

## What was my role?

I led a team of three engineers, owned the architecture, and built the data-fetching layer and chart components.

## How did I approach it?

- Moved aggregation into materialized views in Postgres, refreshed every minute.
- Rendered dashboards with React Server Components so charts stream in as data arrives.
- Added a shared chart library with consistent, accessible colors.

## Which stack did I use and why?

**Next.js** for server rendering and streaming, **Postgres** because the data already lived there, and **Tailwind CSS** for fast, consistent styling.

## What were the results?

Median load time dropped from 6.2s to 1.1s, weekly active usage doubled within three months, and the legacy service was shut down.
